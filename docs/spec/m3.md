# M3 — Scene Analysis Specification

## M3a — Analysis Foundations (this spec)

Fixed decisions for M3a. M3a delivers CPU-only contracts and pure logic
plus fixture adapters; it does NOT wire real detectors (that is M3b),
does NOT implement the analysis stage or script (M3c), and does NOT
touch faces/layouts/candidates (M4/M6).

## Scope

- CPU-only. Analysis never uses the GPU — no CUDA, no GPU models.
- Inputs (produced by M1, per-job under `data/jobs/<job_id>/`):
  - `proxy.mp4` — shot detection input
  - `audio.wav` — silence and energy input (M1 guarantees 16kHz mono pcm_s16le)
- Analysis does NOT require M2 transcript artifacts (words/sentences).
  It can run before, after, or without transcription.

## Stage Names

- `shots` — shot boundary detection on `proxy.mp4`
- `silence` — silence region detection on `audio.wav`
- `energy` — RMS energy windows from `audio.wav`

## Artifacts (schema_version=1)

All artifacts are JSON files with `schema_version: 1`:

### shots.json
```json
{ "schema_version": 1, "shots": [{ "start": float, "end": float }] }
```

### silence.json
```json
{
  "schema_version": 1,
  "noise_db": -35.0,
  "min_dur": 0.5,
  "regions": [{ "start": float, "end": float }]
}
```

### energy.json
```json
{
  "schema_version": 1,
  "window_s": 0.5,
  "windows": [{ "start": float, "end": float, "rms_db": float }]
}
```

## Constants

Module-level constants in code. NO config changes (nothing added to
`Config`), NO environment variables.

| Constant            | Value  | Meaning                                      |
|---------------------|--------|----------------------------------------------|
| `SHOT_THRESHOLD`    | `27.0` | PySceneDetect `ContentDetector` threshold    |
| `SILENCE_NOISE_DB`  | `-35.0`| silencedetect noise floor (dB)               |
| `SILENCE_MIN_DUR`   | `0.5`  | silencedetect minimum silence duration (s)   |
| `ENERGY_WINDOW_S`   | `0.5`  | energy window length (s)                     |

## Rules

### Shots
- `detect_shots(video_path, duration_s) -> list[Shot]`.
- Always returns at least one shot spanning the full duration
  (`Shot(start=0.0, end=duration_s)` when no boundary is found).
- Shots are ordered, non-overlapping, and within `[0, duration_s]`.

### Silence
- ffmpeg command:
  `ffmpeg -hide_banner -nostats -i <audio.wav> -af silencedetect=noise=-35dB:d=0.5 -f null -`
- Parse stderr lines:
  - `silence_start: X`
  - `silence_end: Y | silence_duration: Z`
- Pair starts with ends; a trailing unpaired `silence_start` closes at
  the audio duration.
- Clamp starts `>= 0` and ends `<= duration`; ignore malformed lines
  (unparseable values, `silence_end` without a matching start, zero-length
  regions after clamping).

### Energy
- Read `audio.wav` with stdlib `wave` (M1 guarantees 16kHz mono pcm_s16le);
  samples normalized to floats in `[-1, 1]`.
- Non-overlapping windows of 0.5s.
- The final window may be shorter; include it if `>= 0.1`s, skip if `< 0.1`s.
- `rms_db = 20 * log10(max(rms, 1e-6))` — the floor makes silent windows
  exactly `-120.0 dB`.

## Job States

Per-stage behavior (implemented in M3c):
- `queued -> running` before work starts
- `-> queued` (back to idle) on success
- `-> failed` (job `failed`) on error

## Implementation Constraints

- Lazy imports for heavy libs (numpy is fine at module level; opencv /
  scenedetect / faster-whisper must be imported inside functions — M3b).
- Every adapter has a CPU-only Fixture for tests. All M3a tests run with
  no ffmpeg binary, no scenedetect, and no opencv installed.
- Pure logic modules have no file I/O, no subprocess, and no heavy-lib
  imports beyond numpy at module level.

## M3b Requirements (recorded, NOT implemented here)

- M3b MUST use `opencv-python-headless`, never `opencv-python`
  (this is a headless server; GUI opencv pulls Qt/X11 deps that are
  unavailable/undesired).
- PySceneDetect integration (PySceneDetectAdapter) is deferred to M3b.
- scenedetect / opencv must NOT be added as dependencies in M3a.
