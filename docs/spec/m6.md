# M6 — GPU Face Analysis, Layout & Crop Path (M6a: vision segments + contracts)

Single source of truth for M6. M6a delivers **decisions + config + contracts +
the vision-segment adapter + CPU-only tests ONLY**.

**Out of scope for M6a (M6b+ / M7, do not drift):** face detection, tracking,
layout decision, crop-path math, the M6 stage, the stage script; M7 render is
untouched. DRAFT ClipPlans from M5 (`layout=center_crop`, `crop_path=[]`) are
NOT modified in M6a.

> Note: the M6a task card cited `docs/spec/gpu.md`, which does not exist in
> this repo (checked). Hardware rules below are taken from the project skill
> (`.agents/skills/clipper-project/SKILL.md`) and `docs/spec/pipeline.md`.

## Fixed M6 decisions

1. **GPU0 (RTX 2080 Super) only.** All M6 video decode/encode runs on
   `cuda:0`. The P100s (GPU1/GPU2) have no NVENC/NVDEC and **never** do video.
2. **Analyze ONLY the selected clip ranges**, never the full video. Each
   selected clip gets its own vision segment made from the source
   `[start, end)` window.
3. **Vision segment geometry/timing:**
   - 960x540 fit, **aspect preserved, NO padding** (no `pad` filter).
   - Even dimensions via `scale=trunc(iw/2)*2:trunc(ih/2)*2` (NVENC requires it).
   - `fps = min(native_fps, 30.0)`; if the probed native fps is 0/unknown,
     use **30.0**. (The 3fps/15fps proxies are explicitly NOT acceptable.)
4. **GPU path:** NVDEC decode (`-hwaccel cuda`) + NVENC encode
   (`h264_nvenc -preset p4 -cq 23`).
5. **Detect EVERY frame of the vision segment.** No sparse sampling (the old
   pipeline.md "YuNet at 3fps" line is superseded for the M6 path).
6. **Crop tracks are emitted at NATIVE fps** by linear interpolation between
   detected frames (M6b). `crop_path` timestamps are **CLIP-RELATIVE**
   (`t=0` at clip start) and coordinates are in **SOURCE pixels** (not vision
   proxy pixels).
7. **No face in a clip => `center_crop` with a static path.** Tracking is
   never forced onto a faceless clip.
8. **Track roles:** `main` / `top` / `bottom` / `face`.
9. **CPU face detection only behind an explicit `--cpu-faces` flag, logged
   loudly** (warning printed at run start and in the log). M6a records the
   rule only; the flag is an M6b concern.
10. **Per-clip artifacts live in `data/jobs/<job_id>/clips/<clip_id>/`**
    (vision segment + the later `layout.json`/`face_detections.json`).

## Config (M6a — backward compatible)

```
devices.vision: "cuda:0"     # GPU0 only; P100s never do video
faces.vision_fps_cap: 30.0   # fps = min(native, cap); native 0/unknown -> cap
faces.vision_width: 960
faces.vision_height: 540
```

Existing configs without these keys load unchanged (pydantic defaults).

## ffmpeg command (M6a, exact)

```
ffmpeg -hide_banner -loglevel error -y -hwaccel cuda \
    -ss {start} -to {end} -i {source} \
    -vf "scale={w}:{h}:force_original_aspect_ratio=decrease,scale=trunc(iw/2)*2:trunc(ih/2)*2" \
    -r {fps} -an -c:v h264_nvenc -preset p4 -cq 23 {dst}
```

- Result is **probed** to fill `width`/`height`/`fps`/`frame_count`
  (`nb_frames`; fallback `round((end-start)*fps)`).
- On NVDEC/NVENC failure **raise `MediaError` with the stderr tail — no
  silent CPU/libx264 fallback** (CPU fallback for faces, decision 9, is a
  separate future concern and is not a render fallback).
- `--cpu-faces`: CPU face detection only with this explicit flag, logged
  loudly (decision 9).

## Contracts (M6a, `src/clipper/models/vision_artifacts.py`, schema_version=1)

- `VisionSegmentInfo { clip_id, path, width, height, fps, frame_count,
  source_start, source_end }` — describes one rendered vision segment. It is
  **not** a persisted artifact (no `schema_version`, matching the
  `ProxyInfo`/`AudioInfo` pattern); `source_start`/`source_end` are the
  clip's SOURCE-video times.
- `FaceDetection { t, x, y, w, h, score }` — one detection in a vision
  frame; x/y/w/h **normalized 0..1 relative to the vision frame**; `t` is
  the vision-segment-local timestamp.
- `RegionTrack { role: main|top|bottom|face, keys: list[CropKey] }` — keys
  are the existing M0 `CropKey` (t, x, y, w, h in SOURCE pixels,
  clip-relative t at NATIVE fps).
- `ClipLayoutArtifact { schema_version=1, clip_id, layout: Layout,
  source_width, source_height, native_fps, tracks: list[RegionTrack],
  face_track_count, detector, layout_source: auto|manual }` — the persisted
  per-clip layout artifact (M6b writes it).

## Judgment notes (simplest boring option, per no-drift rule)

- `VisionAdapter.make_segment` accepts an **optional `clip_id` keyword
  (default `"unknown"`)** on top of the card's 7 positional parameters,
  because `VisionSegmentInfo.clip_id` is required. M6b callers pass the real
  clip_id; deriving it from the dst filename was rejected as implicit.
- `FFmpegVisionAdapter.make_segment` also clamps the passed fps to the 30.0
  M6 cap internally, so even a mis-resolved caller fps cannot exceed the
  spec.

## M6b — YuNet ONNX Face Detector on GPU0 (COMPLETE)

M6b delivers the **face DETECTOR ONLY**: pure decode/NMS helpers, the
`FaceDetector` protocol + implementations + factory, model download script,
GPU preflight script, and CPU-only tests.

**Out of scope for M6b (later M6 stages, do not drift):** tracking, layout
decision, crop-path math, the M6 stage, the stage script. M5 DRAFT
ClipPlans are STILL untouched (`layout=center_crop`, `crop_path=[]`,
`status=pending_qc`). M7 untouched.

### M6b decisions

1. **GPU path = YuNet ONNX via `onnxruntime` `CUDAExecutionProvider` on
   GPU0** (index parsed from `cfg.devices.vision`, decision 1). The detector
   FAILS LOUDLY (`FaceDetectorError`) if `CUDAExecutionProvider` is not
   available in onnxruntime or not actually selected by the session — it
   NEVER silently runs on CPU (decision 1 + decision 9 asymmetry: CPU is an
   explicit debug path, never a fallback).
2. **CPU path = `cv2.FaceDetectorYN`** (`name()="yunet-cpu"`), explicit
   debug path ONLY, reachable only via `get_face_detector(cfg, cpu=True)`
   (decision 9 — logged loudly). Default factory call is always the GPU path.
3. **Lazy imports:** `onnxruntime` is imported inside
   `YuNetOnnxDetector.__init__`; `clipper.facedec` is dependency-free pure
   Python (no I/O, not even a numpy import) — importing
   `clipper.adapters.faces`/`clipper.facedec` stays light and CPU-only (M6a
   test suite unaffected, no model files, no GPU).
4. **YuNet anchor/prior constants** (module-level in `facedec.py`,
   documented): strides `(8, 16, 32)`, min sizes `(16, 32, 64)`, square
   aspect `1.0`, decode variance `1.0`; 2-class softmax over `conf` with
   foreground index `-1`; the model's `iou` output is accepted but UNUSED
   (hard greedy NMS instead). Deterministic: decode in anchor order; NMS by
   score DESC with ties by index ASC, suppresses IoU >= `nms_threshold`
   (same convention as M4a's candidate NMS), capped at `top_k`.
5. **`FaceDetection` coordinates**: whole frame is resized to
   `det_size x det_size`, so normalization is exactly a scale by the input
   dims → the M6a contract (`x/y/w/h` normalized 0..1 to the frame, `t`
   segment-local, `t`/`score` attached by the detector).
6. **Model file is NEVER downloaded in tests**; `scripts/install_models.sh`
   (manual run only) fetches the OpenCV Zoo YuNet ONNX to
   `data/models/yunet.onnx`, skips if present, prints the target path.

### Config (M6b — backward compatible)

```

faces.score_threshold: 0.6
faces.nms_threshold: 0.3
faces.top_k: 5000

```

Existing configs without these keys load unchanged (pydantic defaults).

insightface explicitly NOT used; `opencv-python-headless` retained —
`opencv-python` forbidden).
