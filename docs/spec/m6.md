# M6 — GPU Face Analysis, Layout & Crop Path (M6a: vision segments + contracts)

Single source of truth for M6. M6a delivers **decisions + config + contracts +
the vision-segment adapter + CPU-only tests ONLY**.

**Out of scope for M6a (M6b+ / M7, do not drift):** face detection, tracking,
layout decision, crop-path math, the M6 stage, the stage script; M7 render is
untouched. DRAFT ClipPlans from M5 (`layout=center_crop`, `crop_path=[]`) are
NOT modified in M6a.

> Note: the M6a task card cited `docs/spec/gpu.md`, which does not exist in
> this repo (checked). Hardware rules below are taken from the project skill
> (`.agents/skills/clipper-project/SKILL.md`) and `docs/spec/pipeline.md`.

## Fixed M6 decisions

1. **GPU0 (RTX 2080 Super) only.** All M6 video decode/encode runs on
   `cuda:0`. The P100s (GPU1/GPU2) have no NVENC/NVDEC and **never** do video.
2. **Analyze ONLY the selected clip ranges**, never the full video. Each
   selected clip gets its own vision segment made from the source
   `[start, end)` window.
3. **Vision segment geometry/timing:**
   - 960x540 fit, **aspect preserved, NO padding** (no `pad` filter).
   - Even dimensions via `scale=trunc(iw/2)*2:trunc(ih/2)*2` (NVENC requires it).
   - `fps = min(native_fps, 30.0)`; if the probed native fps is 0/unknown,
     use **30.0**. (The 3fps/15fps proxies are explicitly NOT acceptable.)
4. **GPU path:** NVDEC decode (`-hwaccel cuda`) + NVENC encode
   (`h264_nvenc -preset p4 -cq 23`).
5. **Detect EVERY frame of the vision segment.** No sparse sampling (the old
   pipeline.md "YuNet at 3fps" line is superseded for the M6 path).
6. **Crop tracks are emitted at NATIVE fps** by linear interpolation between
   detected frames (M6b). `crop_path` timestamps are **CLIP-RELATIVE**
   (`t=0` at clip start) and coordinates are in **SOURCE pixels** (not vision
   proxy pixels).
7. **No face in a clip => `center_crop` with a static path.** Tracking is
   never forced onto a faceless clip.
8. **Track roles:** `main` / `top` / `bottom` / `face`.
9. **CPU face detection only behind an explicit `--cpu-faces` flag, logged
   loudly** (warning printed at run start and in the log). M6a records the
   rule only; the flag is an M6b concern.
10. **Per-clip artifacts live in `data/jobs/<job_id>/clips/<clip_id>/`**
    (vision segment + the later `layout.json`/`face_detections.json`).

## Config (M6a — backward compatible)

```

faces.vision_fps_cap: 30.0   # fps = min(native, cap); native 0/unknown -> cap
faces.vision_width: 960
faces.vision_height: 540
```

Existing configs without these keys load unchanged (pydantic defaults).

## ffmpeg command (M6a, exact)

```
ffmpeg -hide_banner -loglevel error -y -hwaccel cuda \
    -ss {start} -to {end} -i {source} \
    -vf "scale={w}:{h}:force_original_aspect_ratio=decrease,scale=trunc(iw/2)*2:trunc(ih/2)*2" \
    -r {fps} -an -c:v h264_nvenc -preset p4 -cq 23 {dst}
```

- Result is **probed** to fill `width`/`height`/`fps`/`frame_count`
  (`nb_frames`; fallback `round((end-start)*fps)`).
- On NVDEC/NVENC failure **raise `MediaError` with the stderr tail — no
  silent CPU/libx264 fallback** (CPU fallback for faces, decision 9, is a
  separate future concern and is not a render fallback).
- `--cpu-faces`: CPU face detection only with this explicit flag, logged
  loudly (decision 9).

## Contracts (M6a, `src/clipper/models/vision_artifacts.py`, schema_version=1)

- `VisionSegmentInfo { clip_id, path, width, height, fps, frame_count,
  source_start, source_end }` — describes one rendered vision segment. It is
  **not** a persisted artifact (no `schema_version`, matching the
  `ProxyInfo`/`AudioInfo` pattern); `source_start`/`source_end` are the
  clip's SOURCE-video times.
- `FaceDetection { t, x, y, w, h, score }` — one detection in a vision
  frame; x/y/w/h **normalized 0..1 relative to the vision frame**; `t` is
  the vision-segment-local timestamp.
- `RegionTrack { role: main|top|bottom|face, keys: list[CropKey] }` — keys
  are the existing M0 `CropKey` (t, x, y, w, h in SOURCE pixels,
  clip-relative t at NATIVE fps).
- `ClipLayoutArtifact { schema_version=1, clip_id, layout: Layout,
  source_width, source_height, native_fps, tracks: list[RegionTrack],
  face_track_count, detector, layout_source: auto|manual }` — the persisted
  per-clip layout artifact (M6b writes it).

## Judgment notes (simplest boring option, per no-drift rule)

- `VisionAdapter.make_segment` accepts an **optional `clip_id` keyword
  (default `"unknown"`)** on top of the card's 7 positional parameters,
  because `VisionSegmentInfo.clip_id` is required. M6b callers pass the real
  clip_id; deriving it from the dst filename was rejected as implicit.
- `FFmpegVisionAdapter.make_segment` also clamps the passed fps to the 30.0
  M6 cap internally, so even a mis-resolved caller fps cannot exceed the
  spec.

## M6b — YuNet ONNX Face Detector on GPU0 (COMPLETE)

M6b delivers the **face DETECTOR ONLY**: pure decode/NMS helpers, the
`FaceDetector` protocol + implementations + factory, model download script,
GPU preflight script, and CPU-only tests.

**Out of scope for M6b (later M6 stages, do not drift):** tracking, layout
decision, crop-path math, the M6 stage, the stage script. M5 DRAFT
ClipPlans are STILL untouched (`layout=center_crop`, `crop_path=[]`,
`status=pending_qc`). M7 untouched.

### M6b decisions

1. **GPU path = YuNet ONNX via `onnxruntime` `CUDAExecutionProvider` on
   GPU0** (index parsed from `cfg.devices.vision`, decision 1). The detector
   FAILS LOUDLY (`FaceDetectorError`) if `CUDAExecutionProvider` is not
   available in onnxruntime or not actually selected by the session — it
   NEVER silently runs on CPU (decision 1 + decision 9 asymmetry: CPU is an
   explicit debug path, never a fallback).
2. **CPU path = `cv2.FaceDetectorYN`** (`name()="yunet-cpu"`), explicit
   debug path ONLY, reachable only via `get_face_detector(cfg, cpu=True)`
   (decision 9 — logged loudly). Default factory call is always the GPU path.
3. **Lazy imports:** `onnxruntime` is imported inside
   `YuNetOnnxDetector.__init__`; `clipper.facedec` is dependency-free pure
   Python (no I/O, not even a numpy import) — importing
   `clipper.adapters.faces`/`clipper.facedec` stays light and CPU-only (M6a
   test suite unaffected, no model files, no GPU).
4. **YuNet anchor/prior constants** (module-level in `facedec.py`,
   documented): strides `(8, 16, 32)`, min sizes `(16, 32, 64)`, square
   aspect `1.0`, decode variance `1.0`; 2-class softmax over `conf` with
   foreground index `-1`; the model's `iou` output is accepted but UNUSED
   (hard greedy NMS instead). Deterministic: decode in anchor order; NMS by
   score DESC with ties by index ASC, suppresses IoU >= `nms_threshold`
   (same convention as M4a's candidate NMS), capped at `top_k`.
5. **`FaceDetection` coordinates**: whole frame is resized to
   `det_size x det_size`, so normalization is exactly a scale by the input
   dims → the M6a contract (`x/y/w/h` normalized 0..1 to the frame, `t`
   segment-local, `t`/`score` attached by the detector).
6. **Model file is NEVER downloaded in tests**; `scripts/install_models.sh`
   (manual run only) fetches the OpenCV Zoo YuNet ONNX to
   `data/models/yunet.onnx`, skips if present, prints the target path.

## M6c — Face Tracking and Track Statistics (COMPLETE)

M6c delivers **pure tracking + statistics logic ONLY**: greedy IoU
frame-to-frame association, per-track statistics, and a per-clip track
summary. No I/O, no detector imports, no GPU, no numpy.

**Out of scope for M6c (later M6 stages, do not drift):** layout decision,
crop-path math (native-fps interpolation, clip-relative `CropKey`s), the M6
stage, the stage script. DRAFT ClipPlans stay `layout=center_crop`,
`crop_path=[]`, `status=pending_qc`. M7 untouched.

### M6c decisions

1. **`src/clipper/tracking.py` is PURE**: module imports only
   `clipper.models` (contracts); unit-testable with synthetic
   `FaceDetection` objects; no I/O, no adapters, no detector imports.
2. **`associate(detections_by_frame, iou_threshold=0.3, max_gap_frames=3)
   -> list[FaceTrack]`**: greedy IoU matching frame-to-frame against the
   track's most recent box; matching is greedy by IoU DESC with ties broken
   (track_id ASC, detection-index ASC) for determinism. Track IDs are
   `0, 1, 2, …` in **first-appearance order** (stable). Boxes stored as
   `(t, x, y, w, h)` with M6a normalization (x/y/w/h in 0..1, `t`
   segment-local). A track survives up to `max_gap_frames` consecutive
   unmatched frames; `max_gap_frames + 1` misses finalizes it and a later
   re-appearance creates a NEW track. Empty/missing frames count as gaps
   for all active tracks.
3. **`track_stats(track, frame_count, frame_w, frame_h) -> dict`**:
   `persistence = len(boxes) / frame_count`; `mean_area = mean(w*h)`;
   `corner_affinity` = the quadrant ("tl"/"tr"/"bl"/"br") in which the
   box CENTROID spends >= `CORNER_AFFINITY_MIN_FRACTION` (0.8) of the
   track's frames AND `mean_area < CORNER_AFFINITY_MAX_AREA` (0.04) —
   otherwise `None`. Also returns `mean_cx` (used by side-by-side
   separation). `frame_w`/`frame_h` are accepted for API symmetry but
   unused (boxes are already normalized). Empty track or `frame_count <= 0`
   → zeros + `None` (no crash).
4. **`summarize(tracks, frame_count, frame_w, frame_h) -> TrackSummary`**:
   `dominant_track_id` = highest persistence, tie-break LARGER
   `mean_area` (then smallest track_id); `persistent_track_ids` =
   persistence >= `PERSISTENT_THRESHOLD` (0.6), sorted;
   `facecam_candidate_track_ids` = corner_affinity set AND persistence >=
   `FACECAM_PERSISTENCE` (0.8) AND `mean_area < FACECAM_MAX_AREA` (0.04),
   sorted; `side_by_side_pair` = two persistent tracks, horizontally
   separated (centroids on opposite sides of 0.5), `mean_area` within
   `SIDE_BY_SIDE_MAX_RATIO` (2x) of each other — best pair by combined
   persistence, ties by smaller track-id sum, else `None`. No tracks →
   empty summary, no crash (zero faces is a valid state).
5. **Constants** (module-level in `tracking.py`):
   `CORNER_AFFINITY_MIN_FRACTION = 0.8`, `CORNER_AFFINITY_MAX_AREA = 0.04`,
   `PERSISTENT_THRESHOLD = 0.6`, `FACECAM_PERSISTENCE = 0.8`,
   `FACECAM_MAX_AREA = 0.04`, `SIDE_BY_SIDE_MAX_RATIO = 2.0`.
6. **Contract**: new `TrackSummary` model in `clipper.models` (in-memory,
   NOT a persisted artifact — no `schema_version`, mirroring
   `VisionSegmentInfo`/`ProxyInfo`; `dominant_track_id: int|None`,
   `persistent_track_ids: list[int]`,
   `facecam_candidate_track_ids: list[int]`,
   `side_by_side_pair: tuple[int,int]|None`). `FaceTrack` (existing M6
   contract) is the returned track type; `associate` leaves
   `persistence=0.0` / `corner_affinity=None` on it (filled by consumers
   via `track_stats`) — judgment note per no-drift rule.
7. **No new dependencies**; no config changes.

### Tests (M6c — CPU-only, synthetic detections)

`tests/test_tracking.py` (34): single face moving smoothly → one track,
persistence 1.0; two faces side by side → two tracks + side_by_side
detected; small corner face → correct quadrant affinity (tl/tr/bl/br) +

## M6d — Layout Decision and Crop Track Generation (COMPLETE)

M6d delivers **pure layout decision + crop-track math ONLY**: `decide_layout`
and `build_tracks` with the face_track EMA/dead-zone/velocity-clamp/
shot-reset rules. No I/O, no stage, no stage script, no rendering.

**Out of scope for M6d (later M6 / M7, do not drift):** the M6 stage + stage
script (writing `layout.json`/`face_detections.json` under
`data/jobs/<job_id>/clips/<clip_id>/`, decision 10), any wiring of
detector→tracks→layout, M7 render. DRAFT ClipPlans stay
`layout=center_crop` / `crop_path=[]` / `status=pending_qc`.

### M6d decisions

1. **`src/clipper/layouts.py` is PURE**: imports only `math` and
   `clipper.models`; unit-testable with synthetic `FaceTrack`/`TrackSummary`.
   No I/O, no adapters, no GPU, no numpy.
2. **Constants** (module-level in `layouts.py`): `EMA_TAU_S = 0.8`,
   `DEAD_ZONE = 0.20`, `MAX_PAN_FRAC_PER_S = 0.30`, `ASPECT = 9/16` (exact in
   binary FP), plus `FACECAM_ENLARGE = 4.0` (new, see judgment notes).
3. **`decide_layout(summary, source_w, source_h) -> Layout`** — precedence:
   facecam candidate present → `facecam`; `side_by_side_pair` set →
   `split_screen`; any persistent track (persistence >= 0.6, i.e.
   `persistent_track_ids` non-empty) → `face_track`; otherwise
   `center_crop` (**NO FACE IS NORMAL**). `source_w`/`source_h` are on the
   signature (card) but the decision is geometry-free (judgment note below).
4. **`build_tracks(...)` key grid**: every track emits EXACTLY
   `round(duration_s * native_fps) + 1` keys at CLIP-RELATIVE times
   `0.0, 1/fps, 2/fps, …`; coordinates are SOURCE pixels, **integers**,
   inside the source; `w`/`h` are constant per track. Motion tracks are the
   LINEAR INTERPOLATION between computed positions (decision 6).
5. **center_crop**: one track `role="main"`, STATIC. Window = largest
   EXACT 9:16 integer window fitting the source (`w = 9k, h = 16k,
   k = min(source_w // 9, source_h // 16)`, integer-floored center) so
   `w/h == 9/16` holds exactly for every source size.
6. **face_track**: one track `role="main"`. Window `h = source_h`,
   `w = int(round(h * ASPECT))` (clamped to `<= source_w` for very portrait
   sources — judgment note). `x` follows the dominant face centroid:
   target = centroid centered in the window, clamped to
   `[0, source_w - w]`; EMA `alpha = 1 - exp(-dt / EMA_TAU_S)`; dead zone:
   no motion while the centroid is within the central `DEAD_ZONE` (20%) of
   the crop window; velocity clamp `|dx| <= MAX_PAN_FRAC_PER_S * w * dt`;
   **hard reset at shot boundaries** — at each boundary the window jumps
   straight to the new target (event emitted at the boundary time, so
   interpolation does not ramp across the cut). First detection initializes
   `x` hard to the target.
7. **split_screen**: two tracks `role="top"` (pair member 0) and
   `role="bottom"` (pair member 1), one per speaker, each a STATIC crop of
   the face_track window size centered on that speaker's mean centroid
   (clamped to `[0, source_w - w]`).
8. **facecam**: two tracks — `role="main"` (STATIC exact-9:16 centered
   content window, same geometry as center_crop) and `role="face"` (STATIC
   enlarged facecam square on the first — smallest id — facecam candidate's
   mean centroid).
9. **Validation**: `source_w/source_h <= 0`, `source_fps <= 0`, or negative
   duration raise `ValueError`; a layout requiring a track that is not in
   `tracks` (or without a dominant track) raises `ValueError` naming the
   layout + track id.

### Judgment notes (simplest boring option, per no-drift rule)

- **`build_tracks` signature gains ONE required parameter**: the card lists
  `build_tracks(layout, summary, source_w, source_h, native_fps,
  duration_s, shot_boundaries)`, but `TrackSummary` carries only track
  **ids** — the per-frame boxes required for face_track EMA, split/facecam
  speaker centering do not exist on the summary. `tracks: list[FaceTrack]`
  (the M6c `associate` output) is therefore appended as a REQUIRED last
  parameter. All card-listed parameters keep their names and order.
- **`FACECAM_ENLARGE = 4.0`** (new constant): the facecam `face` square is
  `round(max(mean face w, h) * 4)` in SOURCE pixels, clamped to
  `[1, min(source_w, source_h)]`, centered on the candidate's mean centroid.
  "static or smoothed" (card) resolved to STATIC (no motion source in scope).
- `decide_layout`'s `source_w`/`source_h` are unused (decision is
  geometry-free); kept verbatim from the card signature.
- face_track `w` is clamped to `<= source_w` when the source is narrower
  than a full-height 9:16 window (pathological portrait sources);
  x-clamp then stays well-defined.
- center_crop uses the exact-9:16 window (9k x 16k) rather than
  rounding `h * 9/16`, so the ratio is exact for ALL source sizes;
  face_track uses the card's `w = round(h * 9/16)` verbatim.
