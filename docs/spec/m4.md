# M4 — Clip Candidates Generation Specification

## M4a — Candidate Generation Foundations (this spec)

Fixed decisions for M4a. M4a delivers the CPU-only contract, pure candidate
logic, config support, fixtures and tests. It does NOT wire the `candidates`
pipeline stage or a run script (that is a later M4 sub-milestone) and does NOT
implement LLM scoring / selection / cut snapping (M5). It does NOT touch the
M6/M7 GPU spec.

## Purpose

- Bound the number of candidates sent to the LLM in M5.
- `cheap_score` is a PRE-RANK, NOT a quality verdict. It only decides which
  windows survive into the top-K set handed to M5. It must be cheap and
  deterministic, not an attempt to predict clip quality.

## Inputs (per-job, produced by earlier milestones)

- `sentences.json` (M2) — `SentencesArtifact` (`list[Sentence]`)
- `energy.json` (M3) — `EnergyArtifact` (`list[EnergyWindow]`)
- `silence.json` (M3) — `SilenceArtifact` (`list[SilenceRegion]`)

## Stage / Artifact

- Stage name: `candidates`
- Artifact: `candidates.json`, `schema_version = 1`
- Artifact contract: `CandidatesArtifact { schema_version: int = 1,
  candidates: list[Candidate] }` (new, additive — existing contracts
  untouched). `Candidate` already exists in `clipper.models`.

## Constants (module-level in `src/clipper/candidates.py`)

| Constant       | Value  | Meaning                                   |
|----------------|--------|-------------------------------------------|
| `MIN_CLIP_S`   | `15.0` | minimum window duration (s)               |
| `MAX_CLIP_S`   | `75.0` | maximum window duration (s)               |
| `MIN_SENTENCES`| `3`    | minimum sentences per window              |
| `MAX_SENTENCES`| `8`    | maximum sentences per window              |
| `STRIDE`       | `1`    | start-index stride                        |
| `TOP_K`        | `20`   | max candidates to return                  |
| `NMS_IOU`      | `0.5`  | non-max suppression IoU threshold (keep if `< 0.5`) |
| `W_HOOK`       | `0.35` | cheap_score weight: hook                  |
| `W_DENSITY`    | `0.20` | cheap_score weight: density               |
| `W_ENERGY`     | `0.20` | cheap_score weight: energy                |
| `W_SILENCE`    | `0.10` | cheap_score weight: silence               |
| `W_NICHE`      | `0.15` | cheap_score weight: niche                 |

## Window rule

For each start index `i` (stepping by `STRIDE`), for each length
`L` in `MIN_SENTENCES..MAX_SENTENCES` inclusive:
- `end_idx = i + L - 1` (must be a valid sentence index)
- `duration = sentences[end_idx].end - sentences[i].start`
- keep only if `MIN_CLIP_S <= duration <= MAX_CLIP_S`

`sentence_range` is INCLUSIVE: `(start_idx, end_idx)`.

## cand_id

```
cand_id = f"{job_id}-c{start_idx:04d}-{end_idx:04d}"
```

`cand_id` is a PRIMARY KEY, so it MUST be globally unique: the `job_id` prefix
plus the unique `(start_idx, end_idx)` pair within the job guarantees this.

## Feature definitions (all clamped to `[0, 1]`)

### hook
Inspect the FIRST sentence's text, lower-cased. Add `+0.25` for each of:
1. contains `?` (literal)
2. starts with who/what/when/where/why/how (first word)
3. contains a negation: not / never / no / don't / can't / won't
4. contains any digit
5. contains a contrast word: but / however / actually / instead
6. contains a superlative: most / best / worst / biggest / greatest

Cap the sum at `1.0`.

Word-list keywords (items 2–6) use whole-word, case-insensitive matching
(`\b` boundaries) so, e.g. `no` does not match inside `note`/`number` and
`most` does not match inside `almost`. That is a deliberate fix here. Items 1
(literal `?`) and 4 (any digit) are literal.

### density
`sum(sentence.end - sentence.start for sentences in window) / window_duration`,
clamped to `[0, 1]`.

### energy
`std` (population, ddof=0) of `rms_db` over the energy windows whose
MIDPOINT falls inside `[start, end]`; value = `min(std / 12.0, 1.0)`;
`0.0` if fewer than 2 such windows.

### silence
`silence_fraction = total_silence_overlap / window_duration`
where `total_silence_overlap` is the sum of each silence region's overlap with
`[start, end]`. Value = `1.0 - min(silence_fraction / 0.25, 1.0)`, clamped
to `[0, 1]`.

### niche
Fraction of the configured niche keywords present in the full window text
(case-insensitive). `0.5` (neutral) if no keywords are configured.
`niche_keywords` for the pure function is a flat sequence of keyword strings;
the pipeline resolves `clips.niche_keywords[niche]` -> that list before calling.

## cheap_score

```
cheap_score = clamp(W_HOOK*hook + W_DENSITY*density + W_ENERGY*energy
                     + W_SILENCE*silence + W_NICHE*niche, 0, 1)
```
rounded to 6 decimals.

## Ordering

`cheap_score` DESC, then `start` ASC, then `end` ASC.
(Concretely: sort key = `(-cheap_score, start_idx, end_idx)` computed on the
rounded score.)

## Selection (greedy non-max suppression)

Iterate candidates in the ordered sequence above. Keep a candidate only if its
temporal IoU against ALREADY-KEPT candidates is `< NMS_IOU` (0.5); else
suppress it. Stop at `TOP_K`.
`IoU = overlap_duration / union_duration` (0.0 when there is no overlap).

## Determinism

Same inputs MUST produce byte-identical `candidates.json`. No wall clock, no
randomness, no dict-ordering hazards; JSON serialized via pydantic
`model_dump_json()`.

## Config (additive, backward compatible)

- `clips.niche_keywords: dict[str, list[str]] = {}` on `ClipsConfig`.
- Existing configs load unchanged (default is an empty mapping).

## M4b — Candidates Stage Wiring (implemented record)

Fixed decisions implemented by `src/clipper/stages/candidates.py` (`run_candidates(job_id, cfg, conn)`) and `scripts/candidates_job.py`:

- **Stage name**: `candidates`. **Artifact**: `data/jobs/<job_id>/candidates.json`, written via `CandidatesArtifact.model_dump_json(indent=2)` + trailing newline (identical to the M4a golden fixture format ⇒ byte-identical across runs).
- **Inputs**: `sentences.json` (M2b — `scripts/transcribe_job.py`), `energy.json` / `silence.json` (M3b — `scripts/analyze_job.py`). A missing input fails with a clean `StageError` naming BOTH the artifact and the milestone stage/script that produces it. Every input must have `schema_version == 1` and validate as its typed model (clean `StageError` on mismatch).
- **Niche keywords**: resolved as `cfg.clips.niche_keywords[job.niche]` → flat string list; empty list when the job has no niche or no mapping (neutral 0.5 niche score).
- **DB**: upsert into the EXISTING `candidates` table (no migration): `cand_id`, `job_id`, `candidate_json = Candidate.model_dump_json()`, `score_json = NULL` (M5 fills it). The job's rows are replaced on each non-skipped run so retries are exact; zero candidates ⇒ zero rows and a VALID success (empty artifact, stage `done`).
- **Skip rule**: only when DB stage state = `done` AND artifact file exists AND `schema_version == 1` (same rule as M3b, shared helpers from `stages/analyze.py`). Done marks started/finished timestamps + `artifact_path`.
- **Job state**: `queued → running → queued` on success; failure marks stage `failed` + error text and job `failed`, then raises a clean `StageError` (retry works).
- **Out of scope (M5)**: LLM scoring, selection, cut snapping. M4a constants/formulas are NOT modified here.
