# M8 — Worker Orchestration (M8a: stage plan + report contracts)

M8 turns the finished per-stage pieces (M1–M7) into a single-job worker.
**M8a (this milestone) delivers the stage plan, the report contracts, and
the DB helpers ONLY. There is NO worker loop yet** — no CLI `run`/`status`,
no watch folder, no systemd, no M9 UI, no M10 posting.

Hardware authority: `SKILL.md` (Hardware + M6/M7 GPU rules) and
`docs/spec/pipeline.md`. There is no `docs/spec/gpu.md`; one is
deliberately NOT created (M6/M7 precedent).

## Fixed M8 decisions (authoritative for M8+ / M8b+)

1. **M8 orchestrates the EXISTING stages. It does not reimplement them.**
   The worker calls the existing `run_*` stage functions (M1 ingest through
   M7 render) in order; stage logic, constants, contracts and artifacts of
   M0–M7 stay untouched.
2. **One job at a time. No concurrency.** The worker picks the oldest
   `queued` job (`db.next_queued_job`), runs it start to finish, then picks
   the next one. No parallel jobs, no parallel stages.
3. **Coarse worker stages** (in `worker_plan.STAGE_PLAN`, exact order):

   | coarse stage | required fine-grained DB stages |
   |---|---|
   | `prep`        | `ingest`, `probe`, `proxy`, `audio` |
   | `transcribe`  | `transcribe`, `sentences` |
   | `analyze`     | `shots`, `silence`, `energy` |
   | `candidates`  | `candidates` |
   | `scoring`     | `scoring` |
   | `selection`   | `selection` |
   | `clip_plans`  | `clip_plans` |
   | `layout`      | `layout` |
   | `render`      | `render` |

4. **Coarse-stage skip rule.** A coarse stage is skipped only when ALL of
   its required fine-grained DB stages are done AND their artifacts exist
   AND `schema_version` is valid (= 1 for JSON artifacts). Implemented
   (pure) as `worker_plan.is_coarse_done(conn, job_id, spec)`. Judgment
   notes M8a-J1..J3 below refine exactly what "done" / "artifacts exist"
   mean.
5. **Job states** (existing `Job` states, no new ones):
   `queued -> running`, then on success `awaiting_qc` when the job
   produced ≥ 1 clip, `done` when it produced zero clips (zero clips is a
   valid success, M5 rule); `failed` on error.
6. **Failure.** A stage error marks the CURRENT fine-grained stage `failed`
   (with the error text), the job `failed`, and the worker STOPS the job
   (later stages are not started). The error lands in `report.json`
   (`JobReport.error` + the stage's `StageReport.error`).
7. **Retry is explicit only.** A failed job re-runs only via an explicit
   `--retry`, which resets ONLY the job's `failed` fine-grained stages to
   `pending` (`db.reset_failed_stages`). Done stages are never re-run
   blindly; completed artifacts are preserved.
8. **`report.json` is written per job** (under `data/jobs/<job_id>/`, and
   mirrored into the `job_reports` DB table via `db.write_job_report`).
   It is a `JobReport` (schema_version=1): stage timings
   (`started_at`/`finished_at` per coarse stage, via `StageReport`),
   artifacts (`artifact_paths`), clip count, and errors.
9. **M8 does not modify the user's main Ollama service**
   (127.0.0.1:11434 — never touched; `deploy/*.service` are reference
   only, no systemd changes; SKILL.md Ollama topology).
10. **LLM stages (scoring, clip_plans metadata) use the existing ephemeral
    managed Ollama runtime** (`llm_runtime.managed_ollama(cfg)`, port 11435,
    GPU1, torn down on success AND failure) — exactly as M5b/M5C-5 already
    do. The worker inherits that policy; it adds no new LLM surface.
11. **GPU stages use GPU0** (RTX 2080 Super) per SKILL.md: M1/M7
    NVDEC/NVENC media, M6 face layout; the P100s (GPU1/GPU2) never do
    video decode/encode.

## Judgment notes (no-drift rule: simplest boring option, recorded)

- **M8a-J1 — both `"done"` and `"completed"` count as done.** The M1/M2
  stages (`ingest`, `probe`, `proxy`, `audio`, `transcribe`, `sentences`)
  write the terminal stage state as `"completed"`; M3+ stages
  (`shots`…`render`) write `"done"`. Changing M1/M2 would touch completed
  milestones, so `worker_plan.DONE_STATES = {"done", "completed"}` accepts
  both.
- **M8a-J2 — `is_coarse_done` trusts the DB row's recorded
  `artifact_path`.** Each stage row already stores the artifact path it
  produced; the check verifies (a) row state is done, (b) that path still
  exists (file or directory), and (c) for `*.json`: valid JSON with
  `schema_version == 1`. `StageSpec.artifacts` (and
  `required_artifacts`) are the canonical expected names — used for plan
  reporting/validation — not a second path source.
- **M8a-J3 — `layout`/`render` coarse artifacts are the `clips/`
  directory.** Both stages are per-clip (artifacts under
  `data/jobs/<job_id>/clips/<clip_id>/`); their DB rows record the `clips`
  directory. The coarse skip check therefore requires the `clips`
  directory to exist; the M8 worker (later step) deep-validates each
  clip's `layout.json` / `render.json` + `final.mp4`, mirroring the M6e/M7d
  per-clip skip rules.
- **M8a-J4 — `StageReport` carries no `schema_version` of its own.** It is
  an embedded sub-record; the persisted artifact `JobReport` (report.json)
  is the versioned contract (`schema_version=1`), matching the
  `ScoredClip`/`Candidate` embedding pattern.
- **M8a-J5 — `write_job_report` is DB-only.** The per-job `report.json`
  FILE is written by the M8 worker loop (later step), which calls
  `write_job_report` to persist the same canonical
  (`model_dump_json(indent=2)`) JSON into `job_reports`.

  `WorkerError`, `worker_lock` (non-blocking `flock` on
  `data/run/worker.lock`; contended lock → `WorkerError`), `run_job`
  (lock → load job, clean error if missing → optional
  `reset_failed_stages` on explicit `retry` → job `running` → iterate

  clean `WorkerError`, later stages never start; on success
  `clip_count` from `clips` → `awaiting_qc` (≥1 clip) / `done` (zero

  lock always released), `run_next` (oldest queued once; loop mode
  polls `poll_s` until stopped; never two jobs concurrently).
- CLI: `run JOB_ID [--retry]`, `run --next [--loop] [--poll S]`,

- Judgment (recorded, no-drift rule): `WorkerError` (not `StageError`)
