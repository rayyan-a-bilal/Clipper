# M9 — QC Dashboard: OPEN design decisions (recorded 2026-12-01, PRE-M9)

Status: **NOT spec'd, NOT built.** This file exists so the M9 task card (and
the design discussion with the user) starts from fixed options instead of
invented defaults. Nothing here is a fixed decision yet — each item is
`PENDING USER DECISION` and must be resolved (and given a decision number
m9-1, m9-2, … with the chosen option + old/current values recorded) BEFORE
any M9 code. Per the no-drift rule: simplest boring option wins when the
user defers.

Context: M9 is the server-hosted QC dashboard (SKILL.md direction: browser is
where the user approves clips and tweaks them). M8 already ships
`run`/`status`/`ls`/`report`; the M9-era CLI `rerender CLIP_ID` /
`approve` / `reject` / `export` commands are STUBS today — M9 either fills
them or the dashboard calls the underlying functions directly. The worker's
one-job-at-a-time lock (`data/run/worker.lock`) already serializes
worker vs. dashboard-triggered work.

## Inventory: what is controllable TODAY (grounding for the decisions below)

| Knob | Where it lives now | Per-clip? |
|---|---|---|
| clip selection, gate failures, weighted scores | `selection.json` (decision per candidate) | per candidate |
| forced layout (facecam/split_screen/face_track/face_follow/center_crop) | `forced_layout` param + `layout_source="manual"` (M6e precedent) | YES (per clip) |
| face-follow on/off + persistence bar | `faces.face_follow_enabled`, `faces.follow_persistence_min` (config + per-run) | per-run only |
| face detection threshold | `faces.score_threshold` + `--score-threshold` per-run precedent (TED footage needs 0.5, default 0.6) | per-run only |
| caption font/size/margins/safe-zones/word limits/karaoke color | `CaptionsConfig` → pure `words_to_ass(words, plan, cfg)` | NO (job-level config only) |
| caption on/off | render stage writes `captions.ass` unconditionally | NO knob today |
| cut in/out points | `refine_cut` deterministic (snap/pad/silence/shot, validate 15–75s LAST) | NO manual override |
| render size/crf/encoder | `RenderConfig` (1080x1920, crf 14, h264_nvenc) | job-level |
| fonts on disk | `assets/fonts/` = Montserrat-ExtraBold ONLY; `install_fonts.sh` pattern (manual) | n/a |
| job failure recovery | `run JOB_ID --retry` = failed stages ONLY (M8 decision 7) — NOT a "tweak & rerender" path | n/a |
| rerender a finished clip with tweaks | **does not exist yet** — `clipper rerender CLIP_ID` stub | M9 to design |

## Open decisions (PENDING USER DECISION)

### m9-x1 — per-clip caption override channel
"Clip 2 with smaller captions" needs a per-clip override of
`CaptionsConfig` knobs (font, font_size, margin_v, safe zones,
max_words_per_group, max_chars_per_line, max_lines, karaoke color).
Options:
- **A (recommended, simplest):** ONE new optional field on the ClipPlan
  contract, `caption_overrides: dict | None = None` (additive; validate
  keys against `CaptionsConfig`; render stage merges `cfg.captions` →
  overrides before `words_to_ass`). Needs `docs/spec/contracts.md` mirror
  + an M5C-5-era contract decision entry (M5 rule: ClipPlans are M5C
  contracts — change requires spec decision first).
- **B:** separate per-clip artifact `clips/<clip_id>/caption_overrides.json`
  (no contract change; one more file contract + validator).
- **C:** `clips` table column `overrides_json` (DB-side; the `clips`
  table already stores `plan_json`).
Also decide: does "captions OFF" for one clip ride the same channel (e.g.
`caption_overrides: {"enabled": false}`)? That is a NEW concept (no such
knob exists); probably yes, but it must be its own decision line.

### m9-x2 — manual cut trim ("slight tweaks to my own clip")
Manual in/out overrides on a ClipPlan (respecting `cuts.validate`
15–75s + start<end; overrides bypass the deterministic snaps but STILL
validate). Options: (a) `manual_start`/`manual_end` optional fields on
ClipPlan (render + QC read them); (b) re-run selection/refine with
shifted `refine_cut` params (no contract change, but less honest to the
user). UX: numeric fields first; drag-on-timeline only if the user asks.
Open: may a manual trim push a clip out of 15–75s? (Recommendation: NO —
validate LAST still applies; user gets a concrete error.)

### m9-x3 — font inventory
Font CHOICE in the dashboard is bounded by installed fonts. Today:
Montserrat ExtraBold only. Decision: keep the font list = files in
`assets/fonts/` (dashboard lists them), `install_fonts.sh` stays the only
add path (manual, user, no auto-download — no-drift rule). Decide the
dashboard default (recommendation: keep Montserrat ExtraBold).

### m9-x4 — "which clip do I choose" — selection control surface
Already available as data: every candidate has a `ClipDecision`
(weighted, gate reasons, suppression, cut-reject reasons). M9 shows this.
OPEN: (a) can the user MANUALLY select a rejected candidate and force a
clip plan (recommendation: YES — reuse `fallback_metadata`, skip LLM; a
"force" flag on the ClipPlan, same spirit as `forced_layout`);
(b) can they nudge gate thresholds (7.2/6/7) from the UI — recommendation:
NO in v1 (changing them invalidates scoring; that's a re-run, not a tweak);
(c) LLM re-scoring is NEVER a dashboard action (M5 rule: batch failure
policy, managed-Ollama, PI-stopped requirement) — confirm.

### m9-x5 — rerender path vs retry (cross-M8 record)
Fixed boundary (M8 decision 7 already says it; restated for M9 cards):
`run JOB_ID --retry` = failure recovery ONLY (failed→pending). UI
rerender-with-tweaks = `rerender CLIP_ID` (fills the M9 stub), which must
(a) hold the M8 worker lock, (b) re-generate captions from the (possibly
overridden) config, (c) never touch other clips' artifacts. Dashboard
"rerender whole job" is OUT (would silently overwrite user tweaks).

### m9-x6 — metadata regen scope
Regenerate title/hook/description/hashtags for one clip from the dashboard:
allowed as a per-clip action using the EXISTING M5c metadata path
(`METADATA_SYSTEM`, batch=1, fallback on failure — never fails the job).
Needs PI-stopped/manual-LLM caveats exactly like M5b. Recommend: v1 =
"regenerate metadata" button, per clip.

### m9-x7 — stack + deps
Planned: FastAPI + Jinja2 + HTMX (per SKILL.md M9 line). These are NEW
dependencies — the card MUST list them for explicit user approval (no-drift
rule). `src/clipper/web/` today is an EMPTY M0 placeholder (only __init__.py)
— M9 either lives there or the placeholder is removed (decision, don't
assume).

### m9-x8 — per-run face knobs into per-clip scope?
`score_threshold` / `face_follow_enabled` / `follow_persistence_min` are
per-run today. Dashboard flow for one clip with bad faces: "re-run layout
for this clip with threshold 0.5". Decide if M9 threads these as per-clip
layout overrides (same channel shape as m9-x1) rather than editing config.
Recommendation: YES per-clip for the dashboard; config stays the default.
