## Open decisions (RESOLVED by m9-1 … m9-8 — see `## Decisions` at the end of this file; historical record below)

### m9-x1 — per-clip caption override channel
"Clip 2 with smaller captions" needs a per-clip override of
`CaptionsConfig` knobs (font, font_size, margin_v, safe zones,
max_words_per_group, max_chars_per_line, max_lines, karaoke color).
Options:
- **A (recommended, simplest):** ONE new optional field on the ClipPlan
  contract, `caption_overrides: dict | None = None` (additive; validate
  keys against `CaptionsConfig`; render stage merges `cfg.captions` →
  overrides before `words_to_ass`). Needs `docs/spec/contracts.md` mirror
  + an M5C-5-era contract decision entry (M5 rule: ClipPlans are M5C
  contracts — change requires spec decision first).
- **B:** separate per-clip artifact `clips/<clip_id>/caption_overrides.json`
  (no contract change; one more file contract + validator).
- **C:** `clips` table column `overrides_json` (DB-side; the `clips`
  table already stores `plan_json`).
Also decide: does "captions OFF" for one clip ride the same channel (e.g.
`caption_overrides: {"enabled": false}`)? That is a NEW concept (no such
knob exists); probably yes, but it must be its own decision line.

### m9-x2 — manual cut trim ("slight tweaks to my own clip")
Manual in/out overrides on a ClipPlan (respecting `cuts.validate`
15–75s + start<end; overrides bypass the deterministic snaps but STILL
validate). Options: (a) `manual_start`/`manual_end` optional fields on
ClipPlan (render + QC read them); (b) re-run selection/refine with
shifted `refine_cut` params (no contract change, but less honest to the
user). UX: numeric fields first; drag-on-timeline only if the user asks.
Open: may a manual trim push a clip out of 15–75s? (Recommendation: NO —
validate LAST still applies; user gets a concrete error.)

### m9-x3 — font inventory
Font CHOICE in the dashboard is bounded by installed fonts. Today:
Montserrat ExtraBold only. Decision: keep the font list = files in
`assets/fonts/` (dashboard lists them), `install_fonts.sh` stays the only
add path (manual, user, no auto-download — no-drift rule). Decide the
dashboard default (recommendation: keep Montserrat ExtraBold).

### m9-x4 — "which clip do I choose" — selection control surface

OPEN: (a) can the user MANUALLY select a rejected candidate and force a

## Decisions (recorded 2026-12-01, pre-M9)

These entries resolve open items m9-x1 … m9-x8 and add m9-9 … m9-11.
The open-item table above is retained as historical record; THESE entries are
authoritative. All contract changes are additive optional fields with defaults
that preserve current behaviour; schema_version stays 1. No M0–M7 stage logic,
constants, prompts, or config defaults are edited. Mirror the contract additions

### m9-1 — Per-clip caption override channel (resolves m9-x1; AMENDED)
Chosen: A — additive ClipPlan field, but TYPED, not a raw dict:
  `caption_overrides: CaptionOverrides | None = None`
Old/current: no per-clip caption overrides; caption knobs are job-level config
only; captions always on; no enabled knob.
Rules:
- CaptionOverrides is a pydantic model in src/clipper/models/ with
  `model_config = ConfigDict(extra="forbid")`. Unknown keys are a hard error.
- Fields (all `| None = None`): enabled, hook_enabled, burn_in, font, size,
  margin_v, margin_l, margin_r, safe_top, safe_right, safe_zone_platform,
  max_words, max_line_chars, max_lines, primary, highlight, outline, shadow,
  bold, karaoke.
- Bounds: size 40..160; margin_v 0..900; margin_l/margin_r 0..400;
  safe_top 0..600; safe_right 0..400; max_words 1..8; max_line_chars 8..40;
  max_lines 1..3; outline 0..8; shadow 0..8.
- burn_in: Literal["full","captions_only","none"].
- safe_zone_platform: Literal["tiktok","shorts","reels","none"] (see m9-11).
- Colours stay ASS-native `&HAABBGGRR&` (matches existing cfg.captions.highlight);
  validated by regex. No hex conversion in v1.
- `{"enabled": false}` disables WORD captions for that clip only.
  `{"hook_enabled": false}` disables the hook overlay independently.
  `{"burn_in": "none"}` emits a clean vertical clip with no burned text.
- Resolution is a pure function (see m9-9); stages/adapters receive resolved
  values as arguments, never read overrides themselves.

### m9-2 — Manual cut trims (resolves m9-x2)
Chosen: (a) optional ClipPlan fields
  `manual_start: float | None = None`, `manual_end: float | None = None`
Old/current: no manual trims; start/end come from refine_cut only.
Rules:
- Effective cut = manual_* when set, else original start/end.
- Original auto cut is preserved on the plan for audit; never overwritten.
- Effective cut MUST pass the existing cuts validation path (`cuts.validate`
  per the grounding digest — implementing session confirms the real name).
- Duration MUST remain 15–75s. Out-of-range trims are REJECTED with a concrete
  error naming the actual duration and the violated bound. No silent clamping.
- UX v1: numeric in/out fields + click-a-sentence to set bounds. Timeline drag
  is deferred.

### m9-3 — Font inventory (resolves m9-x3; AMENDED)
Chosen: inventory of REAL FONT FAMILY NAMES, not filename stems.
Old/current: only Montserrat ExtraBold on disk; no picker; the pre-M9 proposal
matched override `font` against filename stems.
Reason for amendment: libass matches the font's internal family name. Passing a
filename stem (e.g. "Inter-Bold") silently falls back to another face.
Rules:
- install_fonts.sh remains the ONLY add path. No auto-download, ever.
- install_fonts.sh builds `assets/fonts/inventory.json` using fontconfig:
    fc-scan --format '%{family}\n' <file>
  if fc-scan is unavailable, fall back to the filename stem AND emit a loud
  warning recorded in the inventory entry.
- Picker lists inventory families. `caption_overrides.font` must match an
  inventory family; otherwise a concrete validation error.
- Default stays Montserrat ExtraBold.
- No new pip dependency (fontconfig is already present for libass).

### m9-4 — Selection control surface (resolves m9-x4)
Chosen: (a) YES force-select · (b) NO gate editing in v1 · (c) confirmed, LLM
re-scoring is never a dashboard action.
Old/current: no force flag; selection is gate-only; no override reason captured.
Rules:
- Additive ClipPlan fields: `forced: bool = False`,
  `force_reason: str | None = None` (optional free text, captured in the UI).
- Force-select builds a ClipPlan from the candidate with NO LLM call:
  cut = candidate bounds + existing padding, validated per m9-2;
  metadata = existing deterministic fallback.
- Gate reasons stay visible; the selection decision records the override.
- Gate thresholds (7.2 / 6 / 7) remain config/spec constants. Editing them
  invalidates scoring and is a re-run, not a dashboard action.
- Demoting an auto-pick is allowed and is not a re-score.

### m9-5 — Rerender vs retry boundary (resolves m9-x5; AMENDED)
Chosen: retry = failure recovery only; dashboard tweaks use `rerender CLIP_ID`.
Amendment: explicit minimal-recompute invalidation + version history.
Old/current: rerender is a stub; no invalidation rules; each render overwrites
final.mp4 with no history.
Rules:
- `run JOB_ID --retry` resets FAILED fine stages to pending only. Unchanged.
- `rerender CLIP_ID` holds the EXISTING worker lock (data/run/worker.lock).
  It never touches other clips. Rerender-whole-job is OUT.
- Dirty-set drives which passes re-run:
    caption/style only  -> ASS -> compose -> thumbnail
                           (REUSE mezzanine.mp4 and audio.m4a)
    manual trim         -> mezzanine -> audio -> ASS -> compose -> thumbnail
    layout/face knobs   -> layout -> mezzanine -> ASS -> compose -> thumbnail
- The only stage artifact rerender may rewrite is THAT clip's layout.json, and
  only via the existing run_layout(clip_id=...) path. words.json, scores.json,
  selection.json, candidates.json are immutable.
- Version history: outputs `final.v<N>.mp4`; `final.mp4` is a copy of the latest;
  `render.json` continues to point at the latest (contract unchanged);
  sibling `render_history.json` records versions. Retain the last 3 versions,
  prune older. Each version stores its resolved override snapshot + dirty set.
- If the worker lock is held, rerender refuses with the holder's job/stage and
  does not queue silently.

### m9-8 — Per-clip face knobs (resolves m9-x8; AMENDED)
Chosen: YES — per-clip, TYPED, same shape as m9-1:
  `layout_overrides: LayoutOverrides | None = None`
Old/current: score_threshold, face_follow_enabled, follow_persistence_min are
per-run only (TED footage needs score_threshold 0.5 vs default 0.6).
Rules:
- LayoutOverrides is a pydantic model, extra="forbid". Fields (all `| None`):
  score_threshold (0.1..0.95), face_follow_enabled (bool),
  follow_persistence_min (0.0..1.0).
- Layout SELECTION is not in this model: the UI sets the existing ClipPlan.layout

- Config remains the default; overrides apply to that clip only.
- `rerender CLIP_ID` re-runs layout for that clip when these change (m9-5).

### m9-9 — Style presets, precedence, provenance (NEW)
Chosen: named style presets + a four-layer resolver with provenance.
Old/current: no presets; caption knobs only from job-level config.
Rules:
- Presets are data: `assets/styles/*.json`, contract StylePreset
  (schema_version, id, label, caption: CaptionOverrides|None,
   layout: LayoutOverrides|None). Ship 2–3 presets; no download path.
- Additive ClipPlan field: `style_id: str | None = None`.
- Job-level layer: `data/jobs/<job_id>/job_overrides.json`, contract JobOverrides
  (schema_version, style_id, caption_overrides, layout_overrides). This is an
  override channel, NOT a stage artifact.
- Precedence, lowest to highest:
    cfg defaults -> style preset -> job override -> clip override
- Within any layer, a safe_zone_platform value expands to its pixel bundle FIRST;
  explicit pixel keys in that same layer win over the expansion (m9-11).
- Pure resolvers, named exactly:
    resolve_caption(cfg, preset, job_ovr, clip_ovr) -> ResolvedCaption
    resolve_layout(cfg, preset, job_ovr, clip_ovr) -> ResolvedLayout
  Each returns resolved values PLUS a per-key source layer
  ("config" | "preset" | "job" | "clip").
- UI shows the source layer per knob and offers "Reset to inherited"
  (clears that key at the clip layer).
- Batch apply: "apply style to all clips in job" / "to selected clips" writes
  clip-layer keys, shows a diff preview, and is undoable.

### m9-10 — Two-tier preview (NEW)
Chosen: instant approximate preview + authoritative single-frame burn.
Old/current: no preview; judging a font requires a full rerender.
Rules:
- Tier 1 (browser, zero server cost): serve assets/fonts via @font-face; overlay
  HTML/CSS captions on the existing thumbnail.jpg scaled from 1080x1920.
  MUST be labelled "approximate". Updates live as knobs change.
- Tier 2 (server, authoritative): burn the real ASS onto ONE frame of the
  existing mezzanine:
    ffmpeg -ss T -i mezzanine.mp4 -vf ass=<captions.ass>:fontsdir=assets/fonts \
           -frames:v 1 preview.png
  Output `clips/<clip_id>/preview.png`, overwritten each call, not versioned.
  Timestamp T is user-selectable within the effective cut.
- Tier 2 reuses the mezzanine and does NOT rerender video. If the mezzanine is
  stale relative to a pending trim/layout change, disable Tier 2 and say why.
- Preview holds the worker lock only for the duration of the frame burn.

### m9-11 — Platform safe zones + burn-in modes (NEW)
Chosen: platform presets as data + independent hook toggle + burn-in mode.
Old/current: safe zones are fixed pixel values (margin_v 450, safe_top 220,
safe_right 150) tuned for TikTok; hook overlay always on; no clean-export mode.
Rules:
- `assets/safe_zones.json` maps platform -> {margin_v, safe_top, safe_right}.
  Keys: tiktok, shorts, reels, none. tiktok reproduces the CURRENT values
  exactly (450 / 220 / 150) so default behaviour is unchanged.
- Selected via caption_overrides.safe_zone_platform at any layer (m9-9).
- burn_in:
    full          -> word captions + hook overlay (current behaviour)
    captions_only -> word captions, no hook
    none          -> no burned text; clean vertical clip
  enabled/hook_enabled are finer-grained switches within full/captions_only.
- Platform presets never change cfg defaults; they resolve at render time.

## M9a judgment notes (implementation record, 2026-12-02)

M9a shipped contracts + data assets only (no resolver, no I/O, no web):

- **M9a-J1 (tiktok safe zone verified, not guessed).**
  `assets/safe_zones.json` ships `tiktok = {margin_v: 450, safe_top: 220,
  safe_right: 150}` and `none = {0, 0, 0}` — verified against the repo:
  `clipper.config` `CaptionsConfig` defaults are `margin_v=450`,
  `safe_zone_top=220`, `safe_zone_right=150`, and `clipper.captions`
  applies `safe_zone_right` (=150) as BOTH `margin_l` and `margin_r`
  (margins 150/150 per the M7a judgment notes, 1080×1080 canvas). The
  digitised bundle (450/220/150) therefore stands as-is. `shorts`/`reels`
  were NOT digitised: `safe_zones.json` v1 contains only `tiktok` and
  `none`; the `safe_zone_platform` `Literal` keeps all four names, and the
  LATER resolver must reject a platform whose bundle is not installed
  ("platform preset not installed", m9-11 behaviour) rather than the UI
  guessing pixels.
- **M9a-J2 (colour regex accepts both ASS hex widths).** m9-1 says colours
  stay ASS-native BGR hex, validated by regex, no conversion in v1. The
  repo's CURRENT values — `captions.py` `SUNG_COLOR="&HFFFFFF&"`,
  `HIGHLIGHT_COLOR="&H00FFFF&"` — use the 6-digit ASS form, and
  `styles/default.json` must equal them (no-op, m9-9), so the model
  regex accepts BOTH the 6-digit (`&HBBGGRR&`) and 8-digit
  (`&HAABBGGRR&`) hex forms. Note: `AA/BB/GG/RR` in m9-1's wording is
  positional notation (alpha/blue/green/red), not literal hex digits —
  `&HAABBGGRR&` as a string is not even valid hex and must not appear in
  data. Tests pin accepted forms (`&H00FFFF&`, `&HFFFFFF&`, 8-digit
  `&H00FFFFFF&`) and reject malformed ones (`yellow`, `#FFFFFF`,
  5/7-digit, missing brackets).
- **M9a-J3 (second preset: `compact`).** Card allows 1–3 presets; one
  additional preset is shipped (`assets/styles/compact.json`): same
  `Montserrat ExtraBold` font, bold, karaoke, white primary; smaller,
  tighter captions (size 64, margin_v 300, margin_l/margin_r 80,
  safe_top 180, safe_right 80, max_words 3, max_line_chars 16, outline 3,
  `safe_zone_platform="none"` with its own explicit pixel keys so m9-11's
  same-layer rule is exercised) plus a lower face `score_threshold` 0.5.
  Values are the M9a implementation's choice; nothing in M0–M8 depends on
  them. `styles/default.json` is asserted equal to the current
  `CaptionsConfig`/`FacesConfig`/`captions.py` constants at runtime
  (`tests/test_m9_assets.py`), i.e. provably a no-op (m9-9).
- **M9a-J4 (resolved-snapshot typing).** Per the card's literal wording,
  `RenderVersion.resolved_caption`/`.resolved_layout` are typed
  `CaptionOverrides | None` / `LayoutOverrides | None` (m9-5 "each version
  stores its resolved override snapshot + dirty set").
  `ResolvedCaption`/`ResolvedLayout` (m9-9) exist as the resolver outputs:
  CONCRETE per-field values + a `sources` dict (field → winning layer,
  `"config"|"preset"|"job"|"clip"`). M9b/M9c may adopt them verbatim for
  `RenderVersion` if a non-nullable snapshot type is wanted — additive
  change, nothing breaks.
