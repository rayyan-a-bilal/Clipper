# M5 — LLM Scoring, Selection & Cut Refinement Constants

Single source of truth for M5b (scoring + selection) and M5c (cut refinement)
so they CANNOT drift. Runtime/client design lives in `docs/spec/llm.md`;
prompt text lives in `src/clipper/prompts.py` (mirrored in
`docs/spec/scoring_prompt.md`).

## Scoring axes

`hook`, `payoff`, `self_contained`, `emotion`, `clarity` — **integers 0-10**.

## Weighted score (M5b)

```
weighted = 0.30*hook + 0.25*payoff + 0.20*self_contained
         + 0.15*emotion + 0.10*clarity
```

## Quality gate (M5b)

A candidate passes the gate IFF:

```
weighted >= 7.2  AND  hook >= 6  AND  self_contained >= 7
```

## Selection (M5b)

- Target from `cfg.clips.target` (default **3** — the current M0–M4 config
  field is `clips.target_count`); cap from `cfg.clips.max` (default **5** —
  config field `clips.max_count`).
- Dedupe by temporal **IoU > 0.30** (keep the higher-weighted clip).
- Backfill from the next eligible (gate-passed, non-duplicate) candidate in
  weighted-descending order until target is met or the list is exhausted
  (cap at max).
- **Zero selected clips is a VALID success** — never fabricate clips, never
  crash the job for an empty result.

## Batch failure policy (M5b)

- Batches of at most `cfg.llm.batch_size` (5) candidates,
  `cfg.llm.max_batch_tokens` (6000) token budget.
- A batch that still fails after `cfg.llm.max_retries` (2) retries:
  **reject those candidates** (drop them from scoring; record the failure),
  **never crash the job**.

## Cut constants (M5c — module-level in `src/clipper/cuts.py`)

```python
SUGGEST_SLACK  = 8.0    # LLM suggestion may deviate from candidate ±8s
SENTENCE_SNAP  = 1.0    # snap suggestion to the nearest sentence boundary <= 1.0s
PAD_START      = 0.120  # word-level padding before the first kept word (s)
PAD_END        = 0.250  # word-level padding after the last kept word (s)
SILENCE_SNAP   = 0.300  # snap to nearby silence region edge (s)
SHOT_SNAP      = 0.400  # snap to nearby shot boundary (s)
```

## Cut order (M5c, strict)

```
clamp suggestion -> sentence snap -> word padding ->
silence snap -> shot snap -> validate 15..75s
```

i.e. each step refines the previous; the final `15 <= dur <= 75` validation
happens LAST and a candidate that violates it is dropped (not crashed on).

## M5 output shape (written by M5b/M5c, consumed by M6+)

- M5 writes **DRAFT** `ClipPlan`s:
  `layout = center_crop`, `crop_path = []`, `status = pending_qc`.
  **M6 replaces `layout`/`crop_path`** (reframe) — M5 must not invent those.
- `clip_id = f"{job_id}-clip{n:02d}"` — `n` is 1-based and selected-clip
  index (not candidate index); the job_id prefix makes it globally unique
  and `clips.clip_id` is the primary key.

## Contracts (M5a, `src/clipper/models/scoring_artifacts.py`)

- `CandidateContext { cand_id, start, end, transcript,
  context_before = "", context_after = "" }`
- `ScoringBatch { schema_version = 1, candidates: list[CandidateContext] }`
  (up to 5 per batch — the REQUEST handed to the model)
- `ScoringResponse { scores: list[ScoredClip] }` — EXACTLY what the model
  returns (one entry per candidate in the batch, same order)
- `ScoresArtifact { schema_version = 1, model, scores: list[ScoredClip] }`
  — the persisted `scores.json` artifact.
- `ScoredClip` itself is unchanged (M0 contract in `clipper.models`).

## Out of scope for M5a (built on top of this spec in M5b/M5c)

M5a delivers the runtime, client, MockLLM, contracts, prompt and config only.
NO scoring stage, NO selection, NO cut snapping yet — all of that must use
the constants above verbatim.
